# Wall Detection Testing System

This directory contains a comprehensive testing and analysis framework for the wall detection system used in the Remalux AR application. The testing system allows for automated evaluation of different models, parameters, and configurations to optimize wall detection performance.

## Components

### Testing Framework Classes

- **TestSceneGenerator**: Creates test environments for wall detection with batch processing support. Handles loading test images, creating test UI, and running automated tests.
- **TestingSettingsManager**: ScriptableObject that manages settings for wall detection testing, including model parameters, UI preferences, and result saving options.
- **TestResultReporter**: Generates reports from wall detection test results, including performance metrics, image comparisons, and statistical analysis.
- **WallDetectionTester**: Analyzes and tests wall detection results, capturing frames, processing images, and saving results.
- **DeepLabModelTester**: Tool for comparing different DeepLabV3 models, measuring performance and visualizing results.

### DeepLab Core Components

- **DeepLabDecoder**: Processes the output of the DeepLabV3 neural network to create a wall mask.
- **BarracudaModelChecker**: Verifies compatibility of ONNX models with the Barracuda inference engine.
- **OnnxImporter**: Handles conversion of ONNX models to Unity's NNModel format.

## How to Use the Testing Framework

### Setup for Testing

1. Create a new scene in Unity and add a GameObject with the `TestSceneGenerator` component.
2. Configure the TestSceneGenerator with models to test:
   - Add NNModel assets to the `modelsToTest` list
   - Provide labels for each model in the `modelLabels` list
3. Set up test images:
   - Add images directly to the `testImages` array, or
   - Enable `loadImagesFromDisk` and specify a path to load images from
4. Create a TestingSettings asset:
   - In the Project window, right-click and select Create > Remalux > Settings > Testing Settings
   - Configure parameters for testing in the created asset
   - Assign the settings asset to the `testSettings` field in TestSceneGenerator
5. Set up UI references:
   - Create UI elements for displaying original images, masks, and results
   - Add buttons for navigation, batch testing, and report generation
   - Assign all UI elements to their respective fields in the TestSceneGenerator

### Running Tests

1. **Single Image Testing**:
   - Use the navigation buttons to browse through test images
   - The current model will process each image and display results in the UI

2. **Batch Testing**:
   - Click the "Run Batch Test" button to process all images with all models
   - Progress will be displayed in the UI
   - Results will be collected and displayed after completion

3. **Generating Reports**:
   - Enable the "Save Result" toggle before running tests to save data
   - Click "Generate Report" after testing to create HTML and JSON reports
   - Reports will be saved to the configured directory

## Customizing Tests

### Model Configuration

Modify the `TestingSettingsManager` asset to configure:
- Available models and their parameters
- Input resolution for each model
- Confidence thresholds
- Post-processing options

### Test Image Management

- Place test images in the configured folder structure
- Enable/disable subfolders in the settings
- Set file type filters as needed

### Result Analysis

- Customize what metrics are captured during testing
- Configure report formats and content
- Set up batch testing parameters (delays, batch size)

## Extending the Framework

To add new testing functionality:
1. Create a new component that inherits from MonoBehaviour
2. Add references to the relevant testing components
3. Implement your custom testing logic
4. Register your component with TestSceneGenerator

## Example Workflow

```csharp
// Example code for programmatically running tests
var testGenerator = FindObjectOfType<TestSceneGenerator>();
var settings = ScriptableObject.CreateInstance<TestingSettingsManager>();

// Configure settings
settings.availableModels.Add(new TestingSettingsManager.ModelSettings { 
    modelName = "MobileNetV3_Small",
    modelPath = "Models/deeplabv3_mobilenet_small",
    inputSize = new Vector2Int(320, 320),
    confidenceThreshold = 0.6f
});

// Assign settings
testGenerator.testSettings = settings;

// Run batch test
testGenerator.StartBatchTest();
```

- Detailed performance metrics for each test
- Visualization of results
- System information
