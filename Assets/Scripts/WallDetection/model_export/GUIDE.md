## 1. Подготовка среды

### 1.1. Установка зависимостей

```bash
# Установка необходимых Python-пакетов
pip install -r requirements.txt
```

### 1.2. Проверка среды

Запустите скрипт проверки окружения:

```bash
# Linux/macOS
./check_env.sh

# Windows
check_env.bat
```

Убедитесь, что все зависимости установлены и среда готова к работе.

## 2. Экспорт моделей

### 2.1. Быстрое тестирование

Для проверки работоспособности системы экспорта запустите тестовый скрипт:

```bash
# Linux/macOS
./run_test.sh

# Windows
run_test.bat
```

Скрипт загрузит тестовое изображение и экспортирует небольшую модель для проверки.

### 2.2. Экспорт всех размеров

Для экспорта моделей разных размеров используйте:

```bash
# Linux/macOS
./export_all_sizes.sh

# Windows
export_all_sizes.bat
```

Это создаст модели с размерами входных данных 224x224, 320x320, 512x512 и 768x768.

### 2.3. Ручной экспорт

Для более гибкого контроля над экспортом используйте:

```bash
# Экспорт MobileNetV3 с размером 320x320 с оптимизацией
python export_mobilenet.py --model_type mobilenet_v3_large --input_size 320 --optimize

# Экспорт ResNet50 с размером 512x512
python export_mobilenet.py --model_type resnet50 --input_size 512 --optimize
```

### 2.4. Проверка результатов

После экспорта проверьте директорию `models/` и убедитесь, что ONNX-файлы были созданы. Если вы использовали параметр `--test_image`, проверьте директорию `models/test_results/` для визуализации результатов сегментации.

## 3. Анализ моделей

### 3.1. Запуск анализа

После экспорта моделей запустите анализатор:

```bash
# Linux/macOS
./analyze_models.sh

# Windows
analyze_models.bat
```

### 3.2. Расширенные опции анализа

```bash
# С экспортом CSV для дополнительного анализа
./analyze_models.sh --csv

# Анализ моделей в другой директории
./analyze_models.sh --models_dir=path/to/models --output_dir=path/to/reports
```

### 3.3. Просмотр результатов

Откройте сгенерированный HTML-отчет в браузере:

```bash
# Linux/macOS
open model_analysis/model_comparison.html

# Windows
start model_analysis\model_comparison.html
```

Отчет содержит:
- Сравнительную таблицу всех моделей
- Графики размера и количества параметров
- Детальный анализ каждой модели
- Рекомендации по выбору

## 4. Интеграция с Unity

### 4.1. Импорт моделей

1. Откройте ваш Unity-проект
2. Создайте директорию `Assets/Resources/Models` если она не существует
3. Скопируйте выбранные ONNX-модели в эту директорию
4. Убедитесь, что модели отображаются в Project View в Unity

### 4.2. Настройка DeepLabDecoder

1. Найдите объект с компонентом `DeepLabDecoder` в сцене
2. Назначьте ONNX-файл в поле `modelAsset`
3. Установите соответствующий `resolutionPreset`, соответствующий размеру входных данных модели

```csharp
// Параметры выбора разрешения
public enum ResolutionPreset
{
    Low_224x224 = 0,    // Хорошо для слабых устройств
    Medium_320x320 = 1, // Баланс для большинства устройств 
    High_512x512 = 2,   // Высокое качество для производительных устройств
    Ultra_768x768 = 3   // Максимальное качество для топовых устройств
}
```

## 5. Тестирование в Unity

### 5.1. Использование DeepLabModelTester

1. Добавьте компонент `DeepLabModelTester` на объект сцены
2. Настройте список моделей для тестирования
3. Запустите сцену и нажмите "Run Tests" в интерфейсе
4. Проанализируйте результаты производительности и качества сегментации

### 5.2. Тестирование с WallDetectionTester

1. Добавьте компонент `WallDetectionTester` на объект сцены
2. Настройте параметры тестирования и захвата кадров
3. Запустите сцену и соберите данные о качестве распознавания стен с разными моделями

### 5.3. Профилирование производительности

1. Добавьте компонент `PerformanceProfiler` на объект сцены
2. Настройте частоту выборки и параметры логирования
3. Запустите сцену и соберите данные о производительности
4. Экспортируйте логи и проанализируйте их с помощью инструмента `analyze_performance_logs.py`

## 6. Рекомендации по выбору модели

### 6.1. По типу устройства

- **Устройства низкого класса** (старые смартфоны):
  - MobileNetV3 с размером 224x224
  - FPS важнее качества сегментации

- **Устройства среднего класса** (современные смартфоны):
  - MobileNetV3 с размером 320x320
  - Баланс между FPS и качеством сегментации

- **Высокопроизводительные устройства** (флагманские смартфоны, планшеты):
  - MobileNetV3 с размером 512x512 или ResNet50 с размером 320x320
  - Качество сегментации важнее при приемлемом FPS

- **Топовые устройства** (iPad Pro, мощные планшеты):
  - ResNet50 с размером 512x512 или выше
  - Максимальное качество сегментации

### 6.2. По качеству сегментации

- Модели с ResNet50 обеспечивают более точные границы и лучше работают в сложных условиях
- Более высокое разрешение входных данных дает более детальную сегментацию
- MobileNetV3 может пропускать мелкие детали или иметь артефакты на сложных текстурах

### 6.3. По производительности

- Размер входных данных имеет наибольшее влияние на производительность
- Оптимизированные модели могут быть на 10-20% быстрее необработанных
- MobileNetV3 примерно в 2-3 раза быстрее ResNet50 при том же разрешении

## 7. Устранение проблем

### 7.1. Проблемы экспорта

- **Ошибка загрузки модели**:
  - Проверьте подключение к интернету (нужно для скачивания весов)
  - Попробуйте альтернативный метод загрузки (см. код)

- **Ошибка CUDA**:
  - Убедитесь, что драйверы GPU совместимы с установленной версией PyTorch
  - Попробуйте экспортировать на CPU, добавив `CUDA_VISIBLE_DEVICES=-1` перед командой

- **Ошибка памяти при экспорте больших моделей**:
  - Уменьшите размер входных данных модели
  - Освободите память, закрыв другие программы

### 7.2. Проблемы в Unity

- **Ошибка загрузки модели в Barracuda**:
  - Проверьте совместимость версии ONNX (рекомендуется opset 11)
  - Используйте `BarracudaModelChecker` для диагностики
  - Конвертируйте в NNModel при необходимости

- **Низкая производительность**:
  - Уменьшите размер входных данных модели
  - Переключитесь на MobileNetV3 если используете ResNet50
  - Проверьте настройки тепловой оптимизации устройства

- **Проблемы качества распознавания**:
  - Настройте параметры постобработки в DeepLabDecoder
  - Проверьте параметры адаптации к различным условиям освещения
  - Используйте модель большего размера или с ResNet50 бэкбоном
